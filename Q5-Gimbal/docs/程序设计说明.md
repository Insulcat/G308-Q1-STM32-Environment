# 二自由度舵机云台程序设计说明

## 1. 项目目标

本项目使用两块 STM32F103C8T6 将系统划分为主控端和舵机执行端。主控端读取两个电位器与 MPU6050，使用 PA2 按键实时选择控制方式，并通过 HC-05 蓝牙发送水平、俯仰目标角度；执行端解析无线数据，用两路 PWM 控制二自由度云台。两端均使用 HAL 库、CMake 和 FreeRTOS。

## 2. 系统架构

### 2.1 主控端

- `InputTask`：20 ms 周期运行，读取 ADC、更新 MPU6050 姿态、进行按键消抖与模式切换。
- `CommTask`：20 ms 周期运行，取得当前控制状态并发送蓝牙数据包。
- `ControlMutex`：保护两个任务之间共享的模式、目标角度和状态字。
- `q5_control.c/.h`：封装 ADC 映射、MPU6050 初始化与互补滤波、模式管理及数据包发送。

### 2.2 舵机执行端

- USART1 接收中断：每收到一个字节便投递至 `RxByteQueue`。
- `RxTask`：从消息队列取字节，完成帧同步、字段范围检查与异或校验。
- `ServoTask`：20 ms 周期运行，将有效目标角度平滑地转换为 TIM2 两路 PWM。
- `ServoMutex`：保护最近一次有效指令。
- `q5_receiver.c/.h`：封装协议解析、角度限幅、渐进控制和通信超时保护。

这种划分使采集、通信与执行相互解耦，后续可以独立修改传感器算法、通信协议或舵机策略。

## 3. 硬件与引脚

### 3.1 主控端

| 模块 | STM32 引脚 | 说明 |
|---|---|---|
| 电位器 1 OUT | PA0 | ADC1_IN0，水平控制 |
| 电位器 2 OUT | PA1 | ADC1_IN1，俯仰控制 |
| 模式按键 | PA2 与 GND | 上拉输入，按下为低电平 |
| MPU6050 SCL | PB10 | I2C2_SCL |
| MPU6050 SDA | PB11 | I2C2_SDA |
| HC-05 TXD | PA10 | USART1_RX |
| HC-05 RXD | PA9 | USART1_TX |

两个电位器和 MPU6050 使用 3.3 V，HC-05 模块使用 5 V，所有模块共地。主控实测 5 V 导轨为 5.00 V，3.3 V 导轨为 3.29 V。

### 3.2 舵机执行端

| 模块 | STM32 引脚 | 说明 |
|---|---|---|
| 水平舵机信号 | PA0 | TIM2_CH1，50 Hz PWM |
| 俯仰舵机信号 | PA1 | TIM2_CH2，50 Hz PWM |
| HC-05 TXD | PA10 | USART1_RX |
| HC-05 RXD | PA9 | USART1_TX |

执行端 STM32、HC-05 和两个 SG90 使用独立 5 V/3 A 电源适配器供电并共地，避免由 ST-LINK 给舵机供电。舵机红线接 5 V、棕线接 GND、橙线接 PWM 信号。

## 4. 两种控制方式

### 4.1 电位器模式

ADC1 使用 DMA 连续采集 PA0、PA1。程序采用一阶低通形式对采样值进行平滑：

`filtered = (7 × filtered + sample) / 8`

随后把 `0~4095` 线性映射到 `20~160°`，为机械结构预留两端余量。系统上电默认进入该模式。

### 4.2 MPU6050 姿态模式

MPU6050 使用 I2C2，配置为默认量程。程序读取三轴加速度和 X/Y 轴角速度，通过加速度计计算静态姿态，再使用互补滤波融合陀螺仪：

`angle = 0.98 × (angle + gyro × dt) + 0.02 × accelAngle`

横滚角映射到水平舵机，俯仰角映射到俯仰舵机；姿态跟随范围限制为 `±45°`，最后仍限制在舵机安全角度 `20~160°`。

### 4.3 实时切换

PA2 配置为上拉输入，按键接地。软件连续检测稳定电平以消抖，每次有效按下在两种模式间切换。如果 MPU6050 尚未初始化成功，则不会进入姿态模式；运行中连续读取失败时会自动退回电位器模式，并每秒尝试重新初始化传感器。

## 5. 蓝牙配置与通信协议

两块 HC-05 均设置为 `115200, 8N1`：

- 执行端：从机模式 `ROLE=0`，地址 `0026:01:03180F`，名称 `G308_Q5_SLAVE`。
- 主控端：主机模式 `ROLE=1`，`CMODE=0`，绑定上述地址，名称 `G308_Q5_MASTER`。

主控端每 20 ms 发送一个 8 字节二进制数据包：

| 字节 | 字段 | 含义 |
|---|---|---|
| 0 | `0xAA` | 帧头 1 |
| 1 | `0x55` | 帧头 2 |
| 2 | mode | 0：电位器；1：MPU6050 |
| 3 | pan | 水平目标角度 |
| 4 | tilt | 俯仰目标角度 |
| 5 | status | ADC、MPU6050 就绪状态位 |
| 6 | sequence | 循环递增序号 |
| 7 | checksum | 前 7 字节按位异或 |

执行端使用双帧头重新同步，拒绝校验错误、模式越界或角度越界的数据。若 500 ms 未收到有效帧，则目标自动变为 90° 中位，以避免无线链路断开后保持危险姿态。

## 6. 舵机输出策略

TIM2 的两路 PWM 周期均为 20 ms。程序把 `20~160°` 映射为 `1000~2000 μs` 高电平脉宽。为降低突变冲击，每个 20 ms 控制周期最多向目标移动 3°，既能保持响应速度，也能减少云台抖动和机构冲击。

## 7. 遇到的问题及解决过程

### 7.1 HC-05 AT 指令偶尔无返回

部分完整 AT 指令只有在按住模块按键、保持 KEY 高电平时才返回。处理方法是使用 CP2102、38400 波特率和 `\r\n` 结尾，必要时在发送命令期间按住按键。最终通过查询命令确认主从角色、UART、连接模式和绑定地址全部正确。

### 7.2 电源层级与共地容易混淆

主控端同时存在 5 V 和 3.3 V 器件，且 ST-LINK 排针同时提供 3.3 V、5 V。为避免反向供电，只保留一种主控供电路径；舵机端使用独立 5 V/3 A 电源，两个舵机、执行端 STM32 和 HC-05 共地。上电前使用万用表核对短路、导通和电压。

### 7.3 面包板导轨和接插件容易接错

所有电源线、信号线均先根据引脚表连接，再断电逐点进行蜂鸣档导通检查。舵机延长线按实际连接确认，而不是只依赖线色，从而核实 5 V、GND 和信号分别到达正确位置。

### 7.4 俯仰轴转动困难

组装后俯仰舵机一度转动困难。排除供电、通信和程序后，发现是俯仰轴螺丝拧得过紧，导致机械摩擦过大。适当放松并保持支架无明显晃动后，两个舵机恢复正常转动。该问题说明调试时需要同时检查软件、电气和机械负载。

### 7.5 电位器与舵机方向相反

电位器左转时舵机顺时针、右转时舵机逆时针。由于该方向与实际装配方向配合后能够形成正确的人机控制关系，且两个轴表现一致，因此没有额外反转映射；若后续机构方向改变，只需在主控映射中交换上下限。

## 9. AI 辅助使用说明

本题使用 AI 辅助完成需求拆解、CubeMX 引脚规划、主从机 FreeRTOS 架构设计、HC-05 AT 参数核验、接线检查、供电安全检查、故障定位和最终验收步骤设计。提交目录 `AI对话截图` 中的 6 张截图记录了关键过程。硬件接线和上电前检查均由本人使用万用表实际核对，最终功能也由实机测试确认。

## 10. 工程复现

1. 分别打开 `firmware/master` 和 `firmware/slave` 中的 `.ioc` 文件查看或重新生成工程。
2. 使用 CMake 预设构建两个工程；编译产物位于各自的 `build/Debug`，该缓存目录不纳入仓库。
3. 使用 STM32CubeProgrammer 和 ST-LINK 分别烧录主控端、执行端 ELF 文件。
4. 断开不需要的烧录供电，按本文接线与独立电源方案上电。
5. 等待两块 HC-05 自动连接，先测试电位器模式，再按 PA2 测试 MPU6050 模式和实时切换。
